## 1. 프로젝트 개요

### 1-1. 프로젝트명

**Seoul Date App** — 서울 실시간 데이트 코스 추천 서비스

### 1-2. 프로젝트 배경

서울시 열린데이터광장의 실시간 공공 API(혼잡도, 날씨, 문화행사)를 활용하여 현재 상황에 맞는 개인화 데이트 코스를 추천하는 서비스를 구축한다. 기존 정적 추천 방식의 한계를 극복하고, RAG 기반 LLM을 통해 실시간 컨텍스트가 반영된 동적 추천을 제공한다.

### 1-3. 서비스 범위

| 구분 | 내용 |
|---|---|
| 대상 플랫폼 | 웹 브라우저 (PC / Mobile) |
| 대상 지역 | 서울특별시 전 지역 |
| 서비스 언어 | 한국어 |
| 초기 출시 범위 | 회원, 장소, 데이트 코스 추천, AI 추천 |

### 1-4. 기대 효과

- 실시간 혼잡도·날씨 반영으로 불필요한 이동 최소화
- 개인 취향 기반 개인화 추천으로 사용자 만족도 향상
- 서울시 공공데이터 활용으로 정보 신뢰성 확보

### 3-1. 회원 도메인 (user-service)

#### UC-USR-001. 이메일 회원가입

| 항목 | 내용 |
|---|---|
| **우선순위** | P0 |
| **행위자** | 비회원 |
| **설명** | 이메일, 비밀번호, 닉네임으로 회원가입한다 |
| **사전 조건** | 미가입 이메일 |
| **정상 흐름** | ① 이메일 인증 코드 발송 요청 → ② Redis에 6자리 코드 저장(TTL 5분) → ③ 사용자 코드 입력·확인 → ④ Redis 인증 완료 플래그 저장(TTL 10분) → ⑤ 회원가입 정보 제출 → ⑥ tb_user / tb_user_profile 저장 → ⑦ JWT 발급 |
| **예외 흐름** | 이메일 중복 → 409, 코드 만료 → 401, 코드 불일치 → 400 |
| **비고** | 인증 코드는 Redis에만 저장 (DB 미사용) |

#### UC-USR-002. 소셜 로그인 / 가입

| 항목 | 내용 |
|---|---|
| **우선순위** | P0 |

| **정상 흐름** | ① 소셜 Authorization Code 수신 → ② 소셜 Provider Access Token 교환 → ③ 소셜 사용자 정보 조회 → ④ tb_user_social_acnt 조회(기존 회원) 또는 tb_user + tb_user_social_acnt 신규 생성 → ⑤ JWT 발급 |
| **비고** | 동일 이메일 기존 계정 존재 시 소셜 계정 자동 연동 처리 |

## 5. 제약 사항

| 구분 | 내용 |
|---|---|
| **기술 제약** | Java 21 LTS, Spring Boot 3.2, Node.js 20 LTS, NestJS 10 고정 |
| **외부 API 제약** | 서울 열린데이터광장 API 호출 제한 준수 (일별 쿼터) |
| **LLM 비용 제약** | OpenAI gpt-4o-mini 사용. 사용자당 시간당 10회 제한으로 비용 통제 |

| **법적 제약** | 개인정보보호법 준수. 회원 탈퇴 후 30일 이내 개인정보 삭제 처리 |

## 6. 용어 정의

| 용어 | 정의 |
|---|---|
| **데이트 코스** | 2개 이상의 장소로 구성된 순서화된 방문 계획 |
| **혼잡도** | 서울 실시간 도시데이터 API 기준 장소별 혼잡 등급 (여유/보통/약간 붐빔/붐빔) |
| **RAG** | Retrieval-Augmented Generation. 벡터 DB에서 유사 장소를 검색하여 LLM 프롬프트에 포함하는 기법 |
| **Soft Delete** | DB에서 실제 레코드를 삭제하지 않고 삭제 플래그(del_yn)와 시점(del_dt)만 기록하는 방식 |
| **Presigned URL** | MinIO/S3에서 발급하는 일정 시간 동안 유효한 업로드 전용 URL. 서버를 거치지 않고 클라이언트가 직접 업로드 가능 |
| **At-Least-Once** | Kafka 메시지 전달 보장 방식. 중복 수신 가능성이 있으나 메시지 유실 없음 |
| **Circuit Breaker** | 다운스트림 서비스 장애 시 일정 시간 호출을 차단하고 Fallback을 반환하는 패턴 |
| **비정규화** | MSA 환경에서 cross-DB JOIN을 피하기 위해 자주 조회하는 컬럼을 해당 서비스 테이블에 중복 저장하는 전략 |
